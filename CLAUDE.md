# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Minimalist one-entry-per-day journal: Flask + SQLite, no build step, no JS framework, no test suite.

## Commands

```bash
uv run flask --app app run --debug        # dev server, uses ./dev.db (override with JOURNAL_DB)
uv run python scripts/import_obsidian.py ../Obsidian/Journal dev.db unmigrated   # Obsidian import
```

Production runs under gunicorn (single worker + threads); config in [deploy/journal.env.example](deploy/journal.env.example). `TZ` matters: "today" and displayed times use server-local time, while stored timestamps are UTC.

## Architecture

- **[app.py](app.py)** is the whole backend. Schema lives in the `SCHEMA` string and is applied (`CREATE IF NOT EXISTS`, plus WAL) once per process by `init()` at import; there are no migrations. `connect()` registers `pylower()` (Python's `str.lower`) for search. Request bodies are capped by `MAX_CONTENT_LENGTH` (8 MB). Two tables with the same shape: `entries(day PK, body, updated_at)` and `drawings` (body = bare SVG `<path>` stroke outlines). A blank body deletes the row; `all_days()` unions both, so drawing-only days get a calendar dot.
- **Optimistic concurrency:** `entries.updated_at` doubles as the version. The client sends `X-Base-Version` on `PUT /api/entries/<day>` and `PATCH /api/drawings/<day>`; a mismatch returns 409 with the server's text (unless the bodies are identical, e.g. a duplicate save, which just succeeds) and the client asks the user to load theirs, keep mine, or merge. The client side is shared by text and ink in [static/autosave.js](static/autosave.js) (`autosaver()`): one PUT at a time (a save requested mid-flight waits, so it's based on the new version, never a stale one), `keepalive` only for bodies under 32 KB (browsers cap pending keepalive bodies at 64 KB total), refresh on focus/visibility/pageshow deduped and dropped if a save happened meanwhile. PUTs time out after 20 s; bodies whose request failed are remembered (`unsure`, as cyrb53 fingerprints by `hash()`), and a 409 or refresh whose server body is one of them is our own lost save, so its version is adopted instead of raising a conflict. **Local backup:** while the current value differs from the acknowledged `saved` one, `backup()` keeps it in `localStorage` under `draft:<url>` as `{version, value: codec.pack(saved, value), base (the saved text, only when there's a merge), sent (unsure + in-flight fingerprints)}`: 1 s after a change (also during a conflict), on every send, failure, 409 and conflict resolution, and on `pagehide` / tab hide (`flush()`: save, then back up, since a save asked for mid-flight only queues); it's removed once the value is saved, loaded or merged away. Every access is in try/catch; a failed write only shows "Not backed up on this device" (and ", not backed up" in a failed save's status), saving is unaffected. A failed write leaves the previous backup in place (an earlier state, still safe to restore). `restore()`, called once each page has shown the server's body (end of `editor.js` / `ink.js`), unpacks the backup onto the server's value; if that equals the server's, the backup is dropped; else it's shown (`set(codec.format(value))`) and either saved plainly (backup's `version` is the server's) or passed to `showConflict()` with the backup's `version` and `base` restored (so its lost-save check adopts our own unanswered save, the merge gets the right common base, and a reload mid-conflict asks again instead of saving over theirs). Two tabs on one day share the key (last writer wins; the other tab still has its own copy in memory). A tab removes the key only while it still holds the exact string that tab last wrote (or adopted in `restore()`), so an idle tab, which never wrote it, can't delete another tab's unsaved backup. Backups of days not opened again stay until that day is visited. (`merge()` in `editor.js` is a line-wise 3-way merge by [node-diff3](static/vendor/diff3.js) (3.2.1, vendored minus its source-map comment) against the autosaver's `saved` body, the text at the version the edit was based on: non-overlapping edits combine, lines both sides changed get git-style markers; the callback returns whether it was clean). The save runs inside `BEGIN IMMEDIATE`.
- **Ink** ([static/ink.js](static/ink.js)): an `<svg>` under the editor, 700 units wide, ruled in 36-unit rows by a CSS background (`--rows`); `fit()` sets the viewBox height to `SPARE` (6) rows below the lowest stroke (min 11), mirrored by `ink_height()` in `app.py` for export; mid-stroke `grow()` only enlarges it. `main` has `40vh` bottom padding so the last rows (text or ink) can scroll off the screen's edge. The `.ink-float` pill (pen / eraser) sits in the left margin (inside the box below 720px), `place()`d as a `top` percentage at the row of the last stroke's end. Ink CSS targets `.ink-page > svg`, since the pill's icons are SVGs too. Pen/mouse (primary button; button 5, a pen's eraser end, always erases) pointer events collect `[x, y, pressure]`; `outline()` runs them through [perfect-freehand](static/vendor/perfect-freehand.js) (1.2.3, vendored unchanged; `FREEHAND` options, pressure simulated from speed for mice) at `SCALE`× because its thresholds are in pixels, then on pen-up simplifies the outline (Ramer–Douglas–Peucker, 0.1 units). `svgPath()` writes it compactly: an absolute start, then relative `l` steps in whole tenths (no rounding drift), no leading zeros, no space before `-` (`M25.3 60.2l-.9-2.9 .4…Z`). Each stroke is stored exactly as drawn, a filled path (CSS `fill: var(--fg)`), so the body is the svg's `innerHTML` with no conversion either way, and export just wraps it in the `SVG` template. `nums()` parses a path back to absolute coordinates, cached per element in a `WeakMap` (for the eraser's hit test and `fit()`); `ink_height()` sums the relative steps the same way. Touch pointers are ignored (palm rejection). A stroke is tied to its `pointerId` and also ends on `lostpointercapture` (WebKit can drop capture without a `pointerup`). During a conflict the box doesn't draw; a pen-down scrolls to and flashes `#ink-status` instead. `touchstart`/`touchmove` are cancelled for Pencil touches or during a stroke, else iPad Safari turns strokes into scrolls, drags or text selections; other finger touches scroll (`touch-action: pan-y`). The saved body is put back with `innerHTML`, so `PATCH /api/drawings/<day>` only accepts strokes matching `STROKE` (and `INK` describes the whole body) in `app.py`. Same `autosaver()` as the editor via a `codec` (`strokes` in `ink.js`: values are arrays of path data; a save sends `{remove: [indices into the saved strokes], add: [new paths]}` as `application/json` (the codec's `type`; `get_json()` refuses the default `text/plain`) instead of the whole page, which froze the iPad; the server applies it in `versioned()` and answers 409 when the base version is stale; 5 s debounce, own status span, load theirs / keep mine, no merge; its backup (`pack`) is the same change with erased strokes as `hash()`es instead of indices, so it holds only the unsaved strokes (16 digits per erased one), however big the page (real ones reach 3 MB, localStorage holds about 5), and `unpack` replays it onto whatever the server has: erased strokes removed if still there, drawn ones appended unless already there (a save that landed unanswered), only ones matching `STROKE` since it goes back in via `innerHTML`; replayed onto another device's newer drawing, "keep mine" keeps both devices' strokes); every pen-up calls `changed()`, and a save with an unchanged body is skipped. No undo or clear, deliberately. `fit()` also runs `countWords()`, a rough handwritten word count: each stroke's bounding box goes on the 36-unit row holding its middle, and within a row strokes sorted by left edge start a new word when the gap to the word so far exceeds `GAP` (8 units, calibrated against hand counts); it hands the number to `inkWords()` (exported by `editor.js`), and `#words` shows `n + m words` (typed + handwritten) when it's nonzero. Keep `W`/`ROW`/`MIN_ROWS`/`SPARE` in sync with `ink_height()`.
- **Templates:** [templates/base.html](templates/base.html) holds the calendar (with Export) and search `<dialog>`s, opened by the header icons in `_nav.html` (included in each page's header `.meta`), and injects `DAY`, `SEL`, `TODAY`, `DAYS` as JS globals; every page view must pass `days=all_days(db)` and `today=...` for it. Pages extend it via `{% block main %}` / `{% block scripts %}`.
- **Frontend** ([static/](static/)): ES modules (`calendar.js` exports `renderCal`, `editor.js` exports `getText` and `inkWords`; the inline page globals `DAY`, `DAYS`, `BODY`, … are read directly). `calendar.js` renders the calendar overlay from `DAYS` (`openCal()` resets it to `DAY`'s month; `openSearch()`; a click on a dialog's backdrop closes it; `/` and `c` open them); its `t` / Alt+D shortcuts go to the date from the client's clock (`goToday()`), not `TODAY` or the server's `/` redirect; Alt+D is matched on `e.code` because Option+D types `∂` on Mac, and ⌘/Ctrl+D is the browser's bookmark. `editor.js` is a `contenteditable="true"` editor (not `plaintext-only`, which reports Enter as `insertLineBreak`; kept in sync with GTD's `notes.js`) that re-renders Markdown highlighting on every keystroke — the rendered HTML's `textContent` must equal the raw text exactly (markup only wraps, never adds/removes characters), because caret positions are tracked as plain-text offsets. `esc()` writes U+00A0 as `&nbsp;` so the output matches the browser's own serialization and `paint()` can skip re-rendering when `innerHTML` already matches. Each non-empty line is wrapped in a full-width inline-block (`.p`, with a bottom margin for parskip-style gaps, or `.li` for tight list items); the `\n` separators stay outside those wrappers. Non-prose spans (markers, links, code) carry `spellcheck="false"` so the browser's native spellcheck skips them; the `abc` toggle sets `ed.spellcheck` (stored in `localStorage.spellcheck`) and forces a re-render so the browser redraws its underlines. After every edit (`edited()`, `apply()`, undo/redo `step()`), `keepCaretUp()` scrolls so the caret stays at least a third of the visual viewport (above an on-screen keyboard) from its bottom; `hintSoon()` then defers `suggest()` to the next frame if it scrolled, since the scroll event would hide the new hint. Since re-rendering wipes native undo, the editor keeps its own undo history. It also handles autosave (5 s idle debounce, flushed on editor blur, `pagehide` and tab hide), conflict UI, and refreshing on tab focus. `newline()` (Enter, `insertParagraph`; same logic as GTD's `notes.js`) continues a list item from the marker before a collapsed caret (number incremented, checkbox reset to `[ ]`, rules excluded via `RULE`), clears an empty item's marker instead, and still runs `assistType("\n", next)` so the last word gets its fix; Shift+Enter (`insertLineBreak`) is a plain newline. Pasted or dropped HTML with Markdown-expressible formatting goes through `htmlToMarkdown()` (copied verbatim from GTD; anything else pastes as plain text); copy, cut and drag put the raw Markdown on the clipboard; ⌘/Ctrl+B / I run `wrapWith()` (`**` / `_`, toggling). `unsmartRule()` rewrites a line that is exactly `—-` to `---` as it's typed (caret at its end, outside code), since iPad smart punctuation makes that of a typed rule; a lone `—` is left alone.
- **Typing assists** (in `editor.js`, off on iOS/iPadOS/Android, whose keyboards do it natively; detected by UA, or Mac platform + touch points for iPadOS): `assistType()` runs in `beforeinput` and capitalizes sentence starts / `i` / learned names by inserting via `insert(s, back)` itself; `revert()` undoes the last fix on an immediate Backspace. Completion is a `position: fixed` `.ghost` span appended to `<body>` (never inside `#ed`, so `textContent` stays exact), placed at the caret rect; Tab accepts. `GET /api/words` (`vocabulary()` in `app.py`, cached as JSON on `count(*), max(updated_at)`, served with that key as an ETag and `no-cache`) returns `words` (lowercase, ≥5 letters, seen ≥2×, by frequency) and `proper` (lowercase → form, capitalized mid-sentence on ≥2 days since `NAMES_SINCE` (env `JOURNAL_NAMES_SINCE`) and rarely lowercase; headings and table-ish lines don't count).
- **Timestamps** (in `editor.js`): a line starting with `STAMP` (`**HH:MM am.** `, outside code) renders as a `.p` whose first child is a `.stamp` span: visible `H:MM am`, the rest (`**`, leading `0`, `.** `) in display-none `.x` spans, so `textContent` stays exact; CSS puts it absolutely in the left margin (`right: calc(100% + 16px)`), static below 720px; above 720px `main` is `max-width: min(704px, 100% - 120px)` so each gutter is at least 84px (24px body padding + 60px), enough for the stamp and the 44px ink pill; at 720px and below `main` is full width. `stampHere()` (in `beforeinput` `insertText`) prepends `clock()` when the caret is on an empty line, the entry is today's by the client clock (`isToday()`), the char doesn't start structure, and the last stamp above differs; the char then goes through `assistType()` (`sentenceStart()` ignores the stamp). A paste (`insertFromPaste`/`insertFromDrop`) is prefixed with `stampHere(text)` unless it starts with a stamp. `keepOutOfStamp()` (selectionchange) moves a collapsed caret inside a stamp, or at its end but in its DOM, to the stamp's end, or after ArrowLeft (`leftward`) to the end of the previous line; `pointAt()` prefers the next node over the end of a stamp's text. `guardStamp()` handles every `delete*` input: Backspace at a stamp's end / Delete before one removes `\n` + stamp; selections are always deleted by it; other ranges are snapped so a stamp is never cut. `breakBeforeStamp()` makes Enter at a stamp's end insert the newline before the stamp; `emptyStamp()` (in `edited()`) drops a stamp left alone on the caret's line. `count()` strips stamps (`STAMPS`).
- **Theme:** colors are CSS variables in `style.css`, each a `light-dark(light, dark)` pair resolved by `color-scheme`. The ◐ button (`_theme.html`, included in each page's header `.meta`, right of `+`) sets `data-theme` on `<html>` (which pins `color-scheme`) and stores it in `localStorage`, overriding `prefers-color-scheme`; a tiny script in `<head>` applies it before first paint. Same scheme as GTD.
- **Search**: all terms must match, via `instr(pylower(body), term)` (SQLite's `LIKE` only folds ASCII); `snippet()` splits on the terms before escaping so highlights never land inside entities; `/export.zip` dumps every entry as `journal/<day>.md`.
- **GTD capture:** `POST /api/inbox` forwards a one-line title to `GTD_URL` + `/capture` (⌘/ / Ctrl+/ or the `+` button on the entry page; the box is prefilled with `getSelection().toString()`, whitespace collapsed). It requires an `X-Requested-With` header, which forces a CORS preflight, so other sites can't post to it.
- `unmigrated/` (gitignored) holds Obsidian files the importer couldn't map to a `YYYY-MM-DD.md` day. The importer also reads exported `YYYY-MM-DD.svg` drawings (stashing any whose paths don't match `INK`) and never overwrites existing days.
