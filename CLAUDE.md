# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Minimalist one-entry-per-day journal: Flask + SQLite, no build step, no JS framework, no test suite.

## Commands

```bash
uv run flask --app app run --debug        # dev server, uses ./dev.db (override with JOURNAL_DB)
uv run python scripts/import_obsidian.py ../Obsidian/Journal dev.db unmigrated   # Obsidian import
git push home main                        # deploy
```

Production runs under gunicorn on the `home` server (port 5006, single worker + threads); config in [deploy/journal.env.example](deploy/journal.env.example). `TZ` matters: "today" and displayed times use server-local time, while stored timestamps are UTC.

## Architecture

- **[app.py](app.py)** is the whole backend. Schema lives in the `SCHEMA` string and is applied (`CREATE IF NOT EXISTS`, plus WAL) once per process by `init()` at import; there are no migrations. `connect()` registers `pylower()` (Python's `str.lower`) for search. Request bodies are capped by `MAX_CONTENT_LENGTH` (8 MB). Two tables with the same shape: `entries(day PK, body, updated_at)` and `drawings` (body = bare SVG `<path>`s). A blank body deletes the row; `all_days()` unions both, so drawing-only days get a calendar dot.
- **Optimistic concurrency:** `entries.updated_at` doubles as the version. The client sends `X-Base-Version` on `PUT /api/<entries|drawings>/<day>`; a mismatch returns 409 with the server's text (unless the bodies are identical, e.g. a duplicate save, which just succeeds) and the client asks the user to load theirs, keep mine, or merge. The client side is shared by text and ink in [static/autosave.js](static/autosave.js) (`autosaver()`): one PUT at a time (a save requested mid-flight waits, so it's based on the new version, never a stale one), `keepalive` only for bodies under 32 KB (browsers cap pending keepalive bodies at 64 KB total), refresh on focus/visibility/pageshow deduped and dropped if a save happened meanwhile. (`merge()` in `editor.js` wraps the differing middle lines, after trimming shared leading/trailing lines, in git-style markers; no common base, so it's not a 3-way merge). The save runs inside `BEGIN IMMEDIATE`.
- **Ink** ([static/ink.js](static/ink.js)): an `<svg>` under the editor, 700 units wide, ruled in 36-unit rows by a CSS background (`--rows`); `fit()` sets the viewBox height to 4 rows below the lowest stroke (min 11), mirrored by `ink_height()` in `app.py` for export. Pen/mouse (primary button) pointer events collect points in tenths of a unit, skipping points <0.5 units apart; on pen-up they're simplified (Ramer–Douglas–Peucker, 0.3 units). The page draws strokes as curves (`pathData()`: quadratic Béziers between midpoints, each controlled by the pen point between), but stores only the pen points as `<path d="M…L…">`: `show()` turns stored points into curves, `stored()` turns curves back into points (lossless, since `points()` keeps M/L points and each Q's control point), and `smooth()`/`unsmooth()` in `app.py` mirror them for export and import. Parsed points are cached per element in a `WeakMap`. Touch pointers are ignored (palm rejection). `touchstart`/`touchmove` are cancelled for Pencil touches or during a stroke, else iPad Safari turns strokes into scrolls, drags or text selections; other finger touches scroll (`touch-action: pan-y`). The saved body is put back with `innerHTML`, so `PUT /api/drawings/<day>` rejects anything not matching `INK` in `app.py`. Same `autosaver()` as the editor (1 s debounce, own status span, load theirs / keep mine, no merge). Undo is a stack of up to 100 `innerHTML` snapshots (of the curves). Export wraps `smooth()`ed bodies in the `SVG` template (keep `W`/`ROW`/`MIN_ROWS` in sync with `ink_height()`).
- **Templates:** [templates/base.html](templates/base.html) holds the sidebar (search, calendar, export) and injects `DAY`, `SEL`, `TODAY`, `DAYS` as JS globals; every page view must pass `days=all_days(db)` and `today=...` for it. Pages extend it via `{% block main %}` / `{% block scripts %}`.
- **Frontend** ([static/](static/)): ES modules (`calendar.js` exports `renderCal`, `editor.js` exports `getText`; the inline page globals `DAY`, `DAYS`, `BODY`, … are read directly). `calendar.js` renders the sidebar calendar from `DAYS`. `editor.js` is a `contenteditable` editor that re-renders Markdown highlighting on every keystroke — the rendered HTML's `textContent` must equal the raw text exactly (markup only wraps, never adds/removes characters), because caret positions are tracked as plain-text offsets. `esc()` writes U+00A0 as `&nbsp;` so the output matches the browser's own serialization and `paint()` can skip re-rendering when `innerHTML` already matches. Each non-empty line is wrapped in a full-width inline-block (`.p`, with a bottom margin for parskip-style gaps, or `.li` for tight list items); the `\n` separators stay outside those wrappers. Non-prose spans (markers, links, code) carry `spellcheck="false"` so the browser's native spellcheck skips them; the `abc` toggle sets `ed.spellcheck` (stored in `localStorage.spellcheck`) and forces a re-render so the browser redraws its underlines. Since re-rendering wipes native undo, the editor keeps its own undo history. It also handles autosave (5 s idle debounce, flushed on editor blur, `pagehide` and tab hide), conflict UI, and refreshing on tab focus.
- **Typing assists** (in `editor.js`, off on iOS/iPadOS/Android, whose keyboards do it natively; detected by UA, or Mac platform + touch points for iPadOS): `assistType()` runs in `beforeinput` and capitalizes sentence starts / `i` / learned names by inserting via `insert(s, back)` itself; `revert()` undoes the last fix on an immediate Backspace. Completion is a `position: fixed` `.ghost` span appended to `<body>` (never inside `#ed`, so `textContent` stays exact), placed at the caret rect; Tab accepts. `GET /api/words` (`vocabulary()` in `app.py`, cached as JSON on `count(*), max(updated_at)`, served with that key as an ETag and `no-cache`) returns `words` (lowercase, ≥5 letters, seen ≥2×, by frequency) and `proper` (lowercase → form, capitalized mid-sentence on ≥2 days since `NAMES_SINCE` (env `JOURNAL_NAMES_SINCE`) and rarely lowercase; headings and table-ish lines don't count).
- **Timestamps:** Alt/Option+T inserts `**HH:MM am.** `, Alt+Shift+T a `## HH:MM am.` heading line (keydown in `editor.js`, matched on `e.code` because Option+T types `†` on Mac; ⌘/Ctrl+T would be Chrome's new tab).
- **Theme:** colors are CSS variables in `style.css`, each a `light-dark(light, dark)` pair resolved by `color-scheme`. The ◐ button next to search sets `data-theme` on `<html>` (which pins `color-scheme`) and stores it in `localStorage`, overriding `prefers-color-scheme`; a tiny script in `<head>` applies it before first paint. Same scheme as GTD.
- **Search**: all terms must match, via `instr(pylower(body), term)` (SQLite's `LIKE` only folds ASCII); `snippet()` splits on the terms before escaping so highlights never land inside entities; `/export.zip` dumps every entry as `journal/<day>.md`.
- **GTD capture:** `POST /api/inbox` forwards a one-line title to `GTD_URL` + `/capture` (⌘I / Ctrl+I or the `+` button on the entry page). It requires an `X-Requested-With` header, which forces a CORS preflight, so other sites can't post to it.
- `unmigrated/` (gitignored) holds Obsidian files the importer couldn't map to a `YYYY-MM-DD.md` day. The importer also reads exported `YYYY-MM-DD.svg` drawings and never overwrites existing days.
